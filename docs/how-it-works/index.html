How Plumbline works

A general contractor’s estimator receives four bids for the same electrical package in four different formats. The cheapest one is rarely the cheapest one. Plumbline normalizes every bid onto a single scope vocabulary, prices the gaps each vendor left out, and re-ranks them on what they would actually cost.

The low bidder moved from first to last. It also found the arc-flash study required by specification 26 05 73 that none of the four bidders covered, which no side-by-side price comparison can surface. See the leveled comparison.

The division of labor is deliberate. The model reads prose and decides what a sentence means. Everything that produces a number is ordinary code, which is what makes the output reproducible and auditable.

01Deterministic

Intake

A bid arrives with attachments and is hashed with SHA-256 before anything else touches it.

02Deterministic

Extract

Page-aware text from PDF, sheet-aware from Excel, plus the email body when the pricing lives there instead of the attachment.

03AI

Interpret

Claude maps prose onto the fixed scope taxonomy and pulls the figures, constrained by a schema passed as a tool definition.

04Deterministic

Level

Scope gaps priced with estimator-entered values. Ranking, gates, and the award model are all ordinary code.

05Human

Decide

A reviewer approves or rejects each extraction and records a soft award. The system never awards a bid.

Human review required. This console is decision support. It never awards a bid, and every AI-extracted value carries a citation back to the page and section it came from so a reviewer can check it against the source.
